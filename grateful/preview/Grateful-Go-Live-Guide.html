From finished build to live website

Ten steps to switch the site on. In this order.

The website is built and tested. To take real bookings it needs its own accounts: a domain, a database, email, payments and hosting. This guide goes through them one at a time, in the order that avoids waiting. Each step says where to go, what to do, and how you know it worked. Together these steps are the “accounts and launch” part of the audit, about 9 of the 20 points still open.

Running costs are in the costing (about R744 a month, plus PayFast’s fee on each payment). Check each provider’s pricing page when you sign up, because prices change.

Keep the keys safe
  • Passwords and keys go into Vercel only (step 5). Never paste them into email, WhatsApp, a chat or the launch checklist.
  • Keep the database password and the studio key in a password manager. They can’t be recovered, only replaced.
  • If a key is ever exposed, make a new one with the provider, put it in Vercel, and delete the old one.

  1. Register the domain

    Any .co.za registrar

    • Choose the address the studio will use, for example grateful.co.za if it is free.
    • Register it in the company’s name, and keep the registrar login in the password manager.
    • Find the registrar’s DNS settings page. Steps 3 and 5 add records there.

    Done when the studio owns the domain and can open its DNS settings.

  2. Create the database

    supabase.com

    1. Sign up and create a New project called grateful. Pick the region closest to Johannesburg that is offered. Save the database password in the password manager.
    2. Open SQL Editor → New query. Paste the whole of the file supabase/setup-all.sql from the project and press Run. It creates the tables, the double-booking guard and the four services, with no prices.
    3. Open Project Settings → API. You need the Project URL and the service_role key (newer projects call it the secret key). Leave this tab open for step 5.

    For Vercel: SUPABASE_URL SUPABASE_SERVICE_ROLE_KEY

    If the SQL Editor says a table “already exists”, the file has already been run. Nothing is changed or lost.

    Done when the Table Editor lists six tables (bookings, services, availability, payments, contact messages, newsletter subscribers) and services has four rows.

  3. Set up email

    resend.com

    1. Sign up, open Domains → Add domain and enter the domain from step 1.
    2. Resend shows a few DNS records. Add each one on the registrar’s DNS page exactly as shown, then wait for Resend to mark the domain Verified. This can take from minutes to a day.
    3. Open API Keys → Create API key with sending access.
    4. Choose the sending address, for example Grateful <bookings@grateful.co.za>. Replies still reach the studio’s Gmail.

    For Vercel: RESEND_API_KEY EMAIL_FROM

    Done when the domain shows Verified in Resend.

  4. Open PayFast, and its test sandbox

    payfast.io and sandbox.payfast.co.za

    1. Apply for a merchant account in the company’s name. PayFast asks for the business details and the bank account payouts go to.
    2. While that is approved, open the sandbox. It has its own test merchant ID, merchant key and passphrase, and no real money moves.
    3. Use the sandbox values first. The live values come from the live account’s Settings → Developer settings, where you also set its passphrase. You swap them in at step 7.

    For Vercel: PAYFAST_MERCHANT_ID PAYFAST_MERCHANT_KEY PAYFAST_PASSPHRASE

    Card details never touch the website. PayFast’s own page takes the payment and tells the site when it has cleared.

    Done when you have the sandbox ID, key and passphrase to hand.

  5. Put the site online

    vercel.com

    1. Sign up with the GitHub account that holds the website’s code. The costing assumes the Pro plan: Vercel’s free plan is for personal, non-commercial sites.
    2. Add New → Project, import the repository, and set Root Directory to grateful.
    3. Under Environment Variables, add every row of the table below. For the three secrets the site makes itself, a developer runs npm run gen:secrets and pastes the values straight in.
    4. Press Deploy. Then open Settings → Domains, add the domain, and add the DNS records Vercel shows at the registrar.

    Done when the site opens on the studio’s own https address.

  6. Check it is ready

    The site itself

    • Open https://your-domain/api/health. It lists each check as passing or failing, and never shows a key.
    • For the full list with how to fix each item, a developer runs npm run check:launch against the Vercel values. It ends with “Ready to launch.”
    • Two items may still show as not done at this point, and that is expected: PayFast live mode (step 7) and Search Console (step 8).

    Done when every required check passes.

  7. Make a test booking, then go live

    The website and the studio dashboard

    1. Sign in to the dashboard at /studio with the studio key. Set the real opening hours, and the real price and deposit for any service that takes payment.
    2. Book that service on the site as a client would, and pay on PayFast’s sandbox page.
    3. Check that the booking shows as confirmed and paid in the dashboard, and that the confirmation email arrives in a Gmail and an Outlook inbox (look in spam too).
    4. Book a free consultation as well, and send a message from the Contact page.
    5. When all of that works: replace the three PayFast values in Vercel with the live ones, set PAYFAST_SANDBOX to false, and redeploy.

    Done when a real, small payment goes through and the booking appears in the dashboard. Cancel or refund it afterwards.

  8. Tell Google the site exists

    search.google.com/search-console

    1. Add a URL-prefix property for the live address and choose the HTML tag method.
    2. Copy only the content="…" value into GOOGLE_SITE_VERIFICATION in Vercel, redeploy, then press Verify.
    3. Under Sitemaps, submit sitemap.xml. Then inspect the home page address and press Request indexing.

    Done when Search Console says the sitemap was read. Pages usually appear in Google within days.

  9. Claim the Google Business Profile

    business.google.com

    • Add the studio in Mulbarton with the website address, opening hours and category.
    • Add the approved photographs, and ask recent clients to leave a review.
    • For a local studio this does more for search than anything on the website itself.

    Done when Google has verified the profile and it shows on Maps.

  10. Try it on real phones

    An iPhone with Safari and an Android phone with Chrome

    • Open every page, make a booking, send a message, and sign in to the dashboard.
    • Note anything that looks wrong, with the page and phone, and send it for fixing.

    Done when both phones work end to end. The site is live.
